# 注意事项

> 与实际设计不同的点、开发时容易踩的坑，浓缩在此。

---

## 1. 表名 `sys_user`，不是 `user`

`user` 是 MySQL 保留关键字，改名为 `sys_user`。

- Entity 类名：`SysUser`（不是 `User`）
- Mapper/Service 命名：`SysUserMapper`、`SysUserService`
- MyBatis XML 和 SQL 中写 `sys_user`
- 之前设计文档中所有说"user 表"的地方，实际指 `sys_user`

---

## 2. 无 DB 外键，应用层保障关联

所有跨表引用 **不做 FOREIGN KEY 约束**（秒杀场景高并发写入，FK 带来行锁和 DDL 不灵活）。

**开发时必须保障：**

| 引用 | 保障内容 |
|---|---|---|
| `goods.merchant_id` → `sys_user` | 插入/更新时校验 `sys_user.role = 'merchant'` |
| `activity.merchant_id` → `sys_user` | 同上 |
| `seckill_goods.activity_id` → `activity` | 活动存在性校验 |
| `seckill_goods.goods_id` → `goods` | 商品存在性校验 |
| `seckill_order.user_id` → `sys_user` | 用户存在性校验 |
| `seckill_order.activity_id` → `activity` | 活动存在性校验 |
| `seckill_order.seckill_goods_id` → `seckill_goods` | 秒杀商品存在性校验 |
| `user_message.user_id` → `sys_user` | 用户存在性校验 |
| `user_message.activity_id` → `activity` | 活动存在性校验（可空） |

一律在 Service 层用 `existsById` / `lambdaQuery().eq(...).count()` 校验，MyBatis-Plus 的 `selectCount` 足够。

**极端情况：** 应用层校验不是原子性的，高并发下可能出现逻辑外键短暂不一致。秒杀核心链路（订单创建）有 order_token 幂等和 SchedulerX 兜底，容忍度较高。如果未来需要严苛一致性，再用 DB 触发器或 FK 兜底。

---

## 3. `goods` 表只有 `goods_id`，不再有独立 `id`

原设计有 `id`（主键）+ `goods_id`（业务 ID），现合并为 `goods_id` 做主键。

- Entity 中 `@TableId` 注解在 `goodsId` 字段上
- `seckill_goods.goods_id` 关联的是 `goods.goods_id`（不是原 `id`）
- 所有联表查询条件用 `goods_id`，不要用 `id`

---

## 4. `sys_user.email` 必填

注册时必须传，用于密码找回和通知下发。

---

## 5. `user_message` 有 `updated_at` 了

`is_read` 变化时会更新 `updated_at`，Entity 中需要加这个字段。

---

## 6. 不使用 `INT(N)` 语法

MySQL 8.0.17+ 已废弃整数显示宽度，不要写 `INT(11)`、`TINYINT(4)`、`INT(10)`，直接用 `INT`、`TINYINT`。

---

## 7. 黑名单冷加载三层保障

`sys_user.ban_status` 是黑名单事实源，Redis `seckill:blacklist` 是网关层 Read 缓存。三层保障：

| 层级 | 时机 | 操作 | 目的 |
|------|------|------|------|
| ① 启动加载 | 应用启动（`ApplicationRunner`） | DEL + SADD 全量 | Redis 重启后不裸奔 |
| ② 事件驱动 | `UserBanned`/`UserUnbanned` 发布时 | SADD / SREM 单条 | 实时同步，< 100ms |
| ③ 定时对账 | SchedulerX 5min 一轮 | 差量 SADD/SREM（不做 DEL） | 兜底事件丢失/数据漂移 |

**③ 对账算法：**

```
dbSet   = SELECT user_id FROM sys_user WHERE ban_status = 'banned'
redisSet = SMEMBERS seckill:blacklist
SADD toAdd (dbSet - redisSet)
SREM toRemove (redisSet - dbSet)
```

只做差量，不做 DEL——即使对账中途 Redis 挂了，也不会让任何封禁用户漏过。
