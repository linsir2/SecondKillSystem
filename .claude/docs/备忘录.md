# 备忘录 —— 领域行为侵入式治理清单

> 所有标记为 ⚠ 的项目需要在后续迭代中整改。

## 问题模式

Service 层直接调用 `entity.setStatus(...)` 而非通过实体领域方法（`entity.pay()` / `entity.approve()` 等）完成状态转换。
这导致状态机不变量分散在 Service 中，违反 DDD 6.4 节"业务规则在领域对象中"的约定。

## 先行模式（本次已实现，后续照抄）

```java
// Entity
public class SeckillOrder {
    public void pay() {
        if (this.status != OrderStatus.UNPAID)
            throw new IllegalStateException("只能支付待支付订单");
        this.status = OrderStatus.PAID;
        this.payTime = LocalDateTime.now();
    }
}

// Service
public void pay(Long orderNo) {
    SeckillOrder order = orderMapper.selectById(orderNo);
    if (order == null) throw new BusinessException("订单不存在");
    try {
        order.pay();                // ← 实体校验+设状态
    } catch (IllegalStateException e) {
        throw new BusinessException(e.getMessage());
    }
    // 乐观锁 update ...
    eventPublisher.publishEvent(...);  // ← 成功后发事件
}
```
